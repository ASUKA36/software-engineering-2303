# 海外藏中国文物知识问答子系统 — 整体介绍

## 1. 子系统定位

本系统是**软件工程课程/文物数字化项目**中的**知识问答子系统**，面向「海外藏中国文物」主题，为 Web 端用户提供自然语言检索与问答能力。

用户可以用中文提问，例如：

- 「唐代瓷器在海外的分布情况如何？」
- 「青花瓷主要收藏在哪些博物馆？」
- 「哈佛大学博物馆有哪些中国书画藏品？」

系统会结合 **MySQL 结构化馆藏数据**、**Neo4j 知识图谱**（可配置开关）与 **大语言模型（LLM）**，完成检索、推理与回答生成，并在界面上区分 **RAG 检索过程** 与 **最终回答**，支持溯源链接与用户反馈。

---

## 2. 建设目标

| 目标 | 说明 |
|------|------|
| **可检索** | 通过 Agent 调用 MySQL / Neo4j 工具，从真实库表与图谱中获取文物、博物馆、艺术家等事实 |
| **可对话** | 支持多轮会话、流式输出、断线续传，体验接近主流对话产品 |
| **可解释** | 前端展示 RAG 检索步骤（可折叠），回答附来源链接与「事实 / LLM 润色」说明 |
| **可运维** | 提供健康检查、管理员反馈统计，便于课设演示与质量改进 |
| **可对接** | 后端以 REST + WebSocket 暴露能力，前端独立部署，便于与其他子系统集成 |

---

## 3. 系统组成

本子系统采用**前后端分离**架构，由两个工程目录构成：

```
qa_system-frame-opti/
├── qa_system/          # 后端：FastAPI + Agent + 数据库访问（默认 :8000）
└── chat-web/           # 前端：Vue 3 + Vite + Pinia（默认 :5173）
```

### 3.1 后端（qa_system）

- **框架**：FastAPI，提供 REST API、WebSocket 流式通道、Swagger 文档（`/docs`）
- **智能层**：Graph Agent（检索与工具调用）+ Main Agent（基于检索结果生成回答）
- **数据层**：MySQL（文物明细 + 对话历史）、Neo4j（知识图谱，按配置启用）
- **模型层**：任意 **OpenAI 兼容协议** 的大模型（DeepSeek、通义、SenseNova 等均可）

### 3.2 前端（chat-web）

- **框架**：Vue 3 + TypeScript + Vite + Pinia
- **页面**：
  - **问答首页**（`/`）：侧边栏历史会话、消息流、流式输入、推荐问题
  - **管理入口**（`/admin/login`、`/admin`）：反馈统计与不准确回答审核（课设演示用）
- **交互亮点**：
  - WebSocket 实时流式回答
  - RAG 检索过程**可展开 / 可折叠**
  - 回答下方展示博物馆来源链接
  - 有帮助 / 不准确反馈

## 5. 一次完整问答的流程

以下为用户在前端发送一条问题后，系统内部的主要步骤：

1. **创建或复用会话**  
   前端调用 `POST /api/qa/session` 获得 `session_id`，或通过 WebSocket 携带已有 `session_id` 连接。

2. **建立 WebSocket**  
   连接 `ws://<host>:8000/api/qa/ws?session_id=...`，发送 `{ "type": "message", "content": "用户问题" }`。

3. **Graph Agent 检索（RAG）**  
   - 根据问题选择 MySQL `execute_sql` 和/或 Neo4j 图查询等工具  
   - 每一步以 `agent_step` 消息推送到前端，展示为「RAG 检索过程」卡片（支持折叠）  
   - 典型步骤：查询 MySQL → 返回条数 → 结果整理 → 完成

4. **Main Agent 生成回答**  
   - 基于检索上下文，LLM **流式**输出正文（`chunk` 消息）  
   - 结束后发送 `done`，附带 `sources`（博物馆链接）、`has_kg_facts`、`has_llm_content` 等字段

5. **持久化与展示**  
   - 对话写入 MySQL `ai_history` 表  
   - 前端渲染 Markdown 回答、来源链接、备注说明，并支持复制 / 重新提问 / 反馈

6. **断线续传（可选）**  
   若生成过程中页面刷新或网络中断，可通过 `cursor` 与 `resume_remaining` 机制续传未完成的 assistant 消息。

## 6. 核心功能清单

### 6.1 用户问答端

| 功能 | 说明 |
|------|------|
| 多轮对话 | 按 `session_id` 维护上下文，侧边栏切换历史会话 |
| 流式输出 | 打字机效果展示回答，生成中可停止 |
| RAG 过程可视化 | 展示 MySQL / Neo4j / 推理等步骤，**可折叠**，完成后默认收起 |
| 来源溯源 | 回答下方列出博物馆与藏品链接 |
| 内容标注 | 区分「基于知识图谱事实润色」与「纯 LLM 生成」的备注文案 |
| 重新提问 | 对单条用户问题或整条回答链路重试 |
| 质量反馈 | 对回答标记「有帮助 / 不准确」 |

### 6.2 管理端（课设演示）

| 功能 | 说明 |
|------|------|
| 管理员登录 | 密码校验，会话 Token |
| 反馈统计 | 按意图统计不准确率、高频错误问题 Top N |
| 审核列表 | 查看被标记为不准确的「问 + 答」记录 |

### 6.3 后端能力

| 功能 | 说明 |
|------|------|
| 配置开关 | `ENABLE_MYSQL` / `ENABLE_NEO4J` 控制数据源 |
| 健康检查 | `GET /health` 返回服务与数据源开关状态 |
| REST 问答 | `POST /api/qa/ask` 支持非流式调用（供其他子系统） |
| OpenAPI | `/docs` 自动生成接口文档 |

## 7. 数据与知识来源

### 7.1 MySQL

- 库名示例：`overseas_chinese_artifacts`
- **artifact 表**：海外馆藏文物结构化信息（名称、朝代、博物馆、详情 URL 等）
- **ai_history 表**：会话消息、流式状态、`cursor` 续写字段等

### 7.2 Neo4j

- 存储文物、博物馆、艺术家等实体及关系（如馆藏、创作关系）
- 通过 Cypher 查询补充 MySQL 难以表达的**关联推理**（在 `ENABLE_NEO4J=on` 时生效）

### 7.3 大语言模型

- 不绑定单一厂商，通过 `.env` 配置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL_NAME`
- Graph Agent 负责「查什么」；Main Agent 负责「怎么说」

## 8. 对外接口形态

| 类型 | 路径前缀 | 典型用途 |
|------|----------|----------|
| REST | `/api/qa` | 创建/删除会话、拉取历史、提交反馈、非流式提问 |
| WebSocket | `/api/qa/ws` | 流式问答、RAG 步骤推送、停止生成、续传 |
| 管理 | `/api/qa/admin` | 登录、反馈统计、不准确列表 |
| 运维 | `/health` | 探活与配置状态 |

> **说明**：在浏览器地址栏直接访问 `GET /api/qa` 会返回 404，属于正常现象；问答接口需使用 `POST /api/qa/session` 等具体路径，或由前端 / WebSocket 调用。

详细字段与报文格式见 [06 API 接口设计](./06_API接口设计.md)、[04 流式对话与 WebSocket 协议](./04_流式对话与WebSocket协议.md)。

## 9. 部署与运行要点

1. **先启后端、再启前端**（前端依赖后端 API 与 WebSocket）
2. 后端：`uvicorn main:app --reload --host 0.0.0.0 --port 8000`
3. 前端：`cd chat-web && npm run dev`，浏览器访问终端提示的地址（通常 `http://localhost:5173`）
4. 前端通过 `chat-web/.env` 配置后端地址，例如本机联调：

   ```env
   VITE_API_BASE=http://127.0.0.1:8000/api/qa
   VITE_WS_BASE=ws://127.0.0.1:8000/api/qa/ws
   ```

5. 修改 `.env` 后需**重启** `npm run dev`，仅刷新页面不会生效

更完整的安装步骤与排错见项目根目录 [README.md](../../README.md)。

## 10. 双 Agent 设计说明（课设核心）

| Agent | 职责 | 用户可见形态 |
|-------|------|----------------|
| **Graph Agent** | 理解问题、调用数据库/图谱工具、整理检索结果 | 前端「RAG 检索过程」折叠面板 |
| **Main Agent** | 将检索结果组织为自然语言回答，流式输出 | 主回答气泡 + 来源 + 备注 |

这种拆分满足课设要求：**事实数据来自库表/图谱，表述由 LLM 润色**，并在 UI 与接口字段上可追溯、可区分。

## 12. 一句话总结

**海外藏中国文物知识问答子系统**是一个前后端分离的智能问答服务：后端用 **Graph Agent + Main Agent** 串联 MySQL、Neo4j 与 LLM，前端用 **Vue 3** 提供流式对话、可折叠 RAG 过程展示、来源溯源与反馈管理，面向海外馆藏文物领域的自然语言检索与知识服务场景。
