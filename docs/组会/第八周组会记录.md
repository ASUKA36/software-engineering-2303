## 三、本周会议决议

### 3.1 子系统分工

经组内讨论，按任务书五个子系统**一人一组**负责，各组对子系统端到端交付（需求、设计、实现、测试、文档）负主责：

| 子系统 | 负责人 | 核心职责 |
|--------|--------|----------|
| ① 知识图谱构建 | 郭晨沛 | 爬虫、清洗、三元组建模、MySQL + Neo4j 入库；为全平台提供统一数据基础 |
| ② Web 知识服务 | 万玉贤 | 文物浏览/检索/可视化、用户中心；面向 Web 端用户的主要服务入口 |
| ③ 知识问答 | 张芷淇 | 基于图谱的 RAG 问答、意图识别、答案溯源 |
| ④ 掌上博物馆 | 薛度扬 | HarmonyOS 移动端列表/详情/搜索及扩展交互 |
| ⑤ 后台管理 | 陶湘园 | 管理员 RBAC、用户与内容审核、文物与三元组维护 |

**协作原则**：① 为数据上游；②③④ 为消费方；⑤ 对全平台数据与内容进行管控；跨组接口变更须组内同步。

### 3.2 技术路线确定

组会确认各层技术选型如下，作为后续设计与实现的**统一基线**（个别组件可在详细设计中微调，但须组会通报）：

| 层次 | 选定技术 | 说明 |
|------|----------|------|
| 数据采集 | Python + requests / Scrapy；Playwright 处理动态页 | ① 负责；须处理反爬、原图下载、UTF-8 CSV 输出 |
| 关系型数据库 | MySQL 8+ | 文物明细、用户、审核、日志等业务表 |
| 图数据库 | Neo4j | 三元组与关系网络；支持 Cypher 查询 |
| Web 前端 | Vue 3（或 React，② 组最终择一） | UI 组件库 + ECharts / G6 等可视化 |
| 移动端 | HarmonyOS + ArkTS / ArkUI | ④ 负责；至少实现列表、详情、搜索 |
| 后端服务 | Spring Boot 或 Node.js（各子系统可独立部署） | REST API；前后端分离 |
| 智能问答 | LLM API + RAG | 意图→图查询→事实检索→生成回答→来源标注 |
| 工程协作 | Git 仓库、Markdown 文档、定期组会 | 接口约定文档化，禁止各端重复爬馆网 |

### 3.3 数据流与依赖关系（初稿）

```
海外博物馆网站 → ① 爬虫/清洗/建模 → MySQL + Neo4j
                                      ↓
                    ② Web / ③ 问答 / ④ App ← 只读或经约定 API 访问
                                      ↑
                              ⑤ 后台管理（读写业务库、审核 UGC）
```

- 业务应用**不直连**博物馆原站，统一消费 ① 产出数据。  
- ③ 问答须基于图谱事实，禁止无数据时编造答案。  
- 管理员账号与前台用户**隔离**。

### 3.4 阶段里程碑（概览）

| 阶段 | 时间（暂定） | 目标 |
|------|--------------|------|
| 需求与设计 | 第九～十周 | 需求规格、概要设计、接口约定 |
| 数据与图谱 | 第十一周起 | CSV、入库、可查询数据集 |
| Web 与后台 | 第十一周～十二周 | 核心页面、管理端 α 版 |
| 问答与移动 | 第十二周～十三周 | RAG 联调、App 真机演示 |
| 测试与文档 | 第十三周～结课 | 测试报告、用户手册、答辩材料 |
