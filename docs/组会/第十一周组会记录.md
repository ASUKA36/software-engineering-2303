## 三、本周会议决议

### 3.1 数据与库表职责

- **统一由第一组（知识图谱构建子系统）牵头构建数据库**：包括爬虫产出 CSV 与关系型表结构、三元组建模及 Neo4j 图库入库策略。  
- 关系型库侧重：文物明细、博物馆、朝代、媒体资源、用户与角色、审核与日志等；图库侧重：实体、关系及问答/可视化所需的子图查询。

### 3.2 各组对接确认事项

各子系统负责人须在库表初版就绪后完成**接入确认**，书面或群内确认以下要点是否满足本子任务需求：

| 子系统 | 对接确认重点 |
|--------|----------------|
| ② Web 知识服务 | 文物列表/详情/筛选字段、检索与可视化所需关联、溯源 URL |
| ③ 知识问答 | 图查询可覆盖的实体与关系类型、溯源字段、空结果场景 |
| ④ 掌上博物馆 | 列表/详情/搜索字段、用户字段与② 一致性、接口形态（REST 等） |
| ⑤ 后台管理 | 用户/RBAC、文物与三元组维护、审核与操作日志相关表 |

### 3.3 联调原则（重申）

- 文物主数据**单一事实来源**（经① 或经② 代理①）。  
- ③ 通过受控接口读图库/事实层，不对外暴露无鉴权图库端口。  
- 管理员账号与前台用户**隔离**；UGC 须经⑤ 审核后再展示（若本阶段实现 UGC）。
