## 摘要

本课程设计围绕「海外藏中国文物」主题，建设集**数据采集与知识图谱构建**、**Web 端知识服务**、**智能问答**、**移动端浏览**、**后台统一管理**于一体的软件系统。技术路线以**知识图谱**为核心，贯通爬虫清洗、三元组建模、图与关系型混合存储、检索与可视化，并采用**检索增强生成（RAG）**将图谱事实与大语言模型结合，保证问答可追溯、可核验。

## 第一章 绪论

### 1.1 设计目的与意义

大量中国文物收藏于海外博物馆，公众检索、研究与文化传播需求突出。通过本课程设计，在有限时间内实践**完整软件生命周期**：从领域需求出发，完成数据获取、知识组织、服务呈现与运营管理，巩固软件工程中的需求分析、架构设计、实现与测试方法，并接触**知识图谱**与**智能问答**等当前常见技术形态。

### 1.2 设计内容与目标

依据课程任务书，设计并实现「**海外藏中国文物知识管理与服务平台**」，包含以下逻辑组成部分：

1. 知识图谱构建子系统；  
2. 海外文物知识服务子系统（Web）；  
3. 知识问答子系统；  
4. 掌上博物馆；  
5. 后台管理子系统。

**目标**：形成可运行、可说明、文档齐备的软件成果；数据与功能范围与任务书及指导教师确认意见一致。

## 第二章 需求分析

### 2.1 用户与角色

| 角色 | 主要诉求 |
|------|----------|
| 访客/注册用户 | 浏览海外馆藏中国文物、检索、查看关联与统计、使用问答、（可选）收藏与评论等。 |
| 系统管理员 | 用户与权限、文物与图谱数据、审核与日志、系统参数（范围依实现裁剪）。 |
| 内容审核员 | 审核用户生成内容，维护内容安全。 |
| 数据管理员 | 维护文物与三元组数据，导入导出。 |

### 2.2 功能性需求概述

**（1）知识图谱构建**

- 从指定博物馆站点获取中国文物相关信息，字段至少包括：名称、图片（原图或可解析的稳定地址）、年代、类型、材质、介绍文本、详情页 URL 等；**UTF-8 CSV** 及**字段说明**交付。  
- 处理反爬、原图下载与完整性统计；清洗包括标准化、去重、图片链接校验。  
- 三元组建模，实体与关系类型覆盖任务书要求的核心集合；可参考 **CIDOC-CRM** 思想。  
- 外部百科类补充与跨馆实体对齐须可追溯。  
- 双层存储：**图数据库**Neo4j+ **关系型数据库**（MySQL）；
- 支持数据更新策略（全量或增量）。

**（2）Web 知识服务**

- 多视图浏览、筛选排序、详情页、相关推荐、可选文物对比。  
- 简单查询、高级组合查询、图谱关系类查询入口。  
- 可视化：关系图、时间轴、地理分布、统计看板等，**至少实现一项**，
- 结果导出 CSV 或 JSON。  
- 用户注册登录与基础资料；其余社交类功能按任务书选做条款处理。

**（3）知识问答**

- **RAG 架构**：意图/实体 → 图查询 → 检索结果作为上下文 → 大模型生成回答 → **来源标注**。  
- 简单问答类型覆盖任务书所列多类问题中的主要情形；**无数据时明确提示**，禁止伪造事实。  
- 复杂问答、多轮、反馈与闲聊等按选做处理。

**（4）掌上博物馆**

-  **HarmonyOS + ArkTS/ArkUI**；
- 至少包含：文物列表与详情、搜索；扩展能力按进度选做。

**（5）后台管理**

- 管理员独立账号体系；基于角色的权限（超级管理员、审核员、数据管理员等）。  
- 用户管理、内容审核（自动与人工至少具备可演示闭环）、文物与三元组管理、操作日志；备份与监控等按选做或简化实现。

### 2.3 非功能性需求

- **性能**：课堂演示场景下主要页面与查询响应可接受（具体指标可由小组在设计中自定并测试）。  
- **安全**：密码安全存储、后台权限控制、接口基本校验；爬虫与第三方 API 密钥不入公开仓库。  
- **可维护性**：模块划分清晰、配置与代码分离、README 与部署说明完整。  
- **合规**：尊重数据来源版权与 robots 约定；用户上传内容经审核后公开。

## 第三章 系统总体设计

### 3.1 系统架构

采用**前后端分离**与**数据层分层**相结合的结构：

- **表现层**：Web 前端；移动端 App（或等效）；后台管理前端。  
- **应用层**：业务 API、鉴权、问答编排、爬虫与定时任务服务。  
- **数据层**：关系型数据库存业务表与用户数据；图数据库存储三元组及关系网络；必要时引入向量库（若以图搜图等扩展实现）。  
- **外部服务**：大语言模型 API、可选图像审核 API 等。


### 3.2 子系统划分与依赖关系

知识图谱构建子系统为**数据上游**，为 Web 服务、问答、移动端提供统一数据基础；后台管理子系统对全平台数据与内容进行**管控**；问答子系统依赖图谱与（可选）向量检索，调用大模型服务。

依赖关系简述：**构建 → 存储 → 服务 / 问答 / 移动 → 后台监管**。

## 第四章 功能与模块设计

### 4.1 知识图谱构建子系统

| 模块 | 功能要点 |
|------|----------|
| 爬虫子模块 | 多馆数据源、字段解析、反爬与限速、原图下载、CSV 输出与统计报告。 |
| 清洗子模块 | 标准化、去重、图片 URL 校验。 |
| 建模子模块 | 实体/关系定义、三元组生成、URI 规则。 |
| 对齐与补充 | 跨馆实体对齐、外部知识补充与来源标注。 |
| 入库与同步 | 写关系库与图库、更新触发策略。 |

### 4.2 海外文物知识服务子系统（Web）

| 模块 | 功能要点 |
|------|----------|
| 浏览与检索 | 列表/卡片、筛选、详情、推荐、对比（按实现裁剪）。 |
| 查询服务 | 全文检索、高级筛选、图谱查询接口。 |
| 可视化 | 力导向图 / 时间轴 / 地图 / 统计图（实现项在详细设计中固定）。 |
| 用户中心 | 登录注册、个人设置；扩展功能单列。 |

### 4.3 知识问答子系统

| 模块 | 功能要点 |
|------|----------|
| 问题理解 | 意图分类、实体链接、生成图查询语句。 |
| 检索 | 访问图库/关系库获取事实子图或记录集合。 |
| 生成与溯源 | 拼装 Prompt、调用 LLM、解析输出并附加数据来源与链接。 |
| 安全与兜底 | 空结果提示、超时与异常处理。 |

### 4.4 掌上博物馆子系统

| 模块 | 功能要点 |
|------|----------|
| 展示与搜索 | 首页、详情、搜索；音视频与语音能力按实现勾选。 |
| 用户与内容 | 点赞收藏、评论、上传、审核对接；按选做裁剪。 |
| 以图搜图 | 特征提取与相似度检索，默认选做。 |

### 4.5 后台管理子系统

| 模块 | 功能要点 |
|------|----------|
| 权限与账号 | RBAC、管理员与前台用户隔离、操作日志。 |
| 用户与审核 | 用户列表与状态、待审队列、自动审核策略配置（简化可实现）。 |
| 数据管理 | 文物 CRUD、三元组维护、批量导入导出。 |
| 运维扩展 | 备份、监控、系统配置、一致性检查，按选做实现。 |

## 第五章 技术方案与关键技术

### 5.1 推荐技术栈（可按小组选型调整）

| 层次 | 可选技术 |
|------|----------|
| 前端 Web | Vue 3 / React；UI 组件库；ECharts / D3 / G6 等用于可视化。 |
| 移动端 | HarmonyOS ArkTS + ArkUI； |
| 后端 | Spring Boot / Node.js 等；REST 或 GraphQL。 |
| 数据库 | MySQL 8+；Neo4j。 |
| 爬虫 | Python + Scrapy / requests；Playwright / Selenium 处理动态页。 |
| 智能问答 | LLM API + RAG；图查询语言 SPARQL 或 Cypher（与选型一致）。 |
| 工程化 | Git；Docker（可选）；CI（可选）。 |

### 5.2 关键技术说明

1. **反爬与原图**：说明各目标站点的抓取策略、Session/频率控制、原图 URL 解析方式（尤其 API 型站点）。  
2. **知识建模**：给出核心实体关系图（ER/本体示意图）及与 CIDOC-CRM 的对应关系说明。  
3. **双库存储与同步**：说明哪些数据进关系库、哪些进图库、更新时如何保持一致。  
4. **RAG 与溯源**：画出问答数据流；说明如何防止无依据回答。  
5. **权限与安全**：RBAC 模型、敏感操作日志、密钥管理。
