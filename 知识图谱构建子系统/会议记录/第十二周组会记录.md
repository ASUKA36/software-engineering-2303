**字段说明及 CSV 映射关系**定终版，作为各组唯一数据规范。

### 3.2 FastAPI 只读 API

`backend/main.py` 已部署，当前 5 个 GET 接口：

| 接口 | 用途 |
|------|------|
| `/api/health` | 健康检查 |
| `/api/artifacts` | 列表，支持分页和筛选 |
| `/api/artifacts/{museum_id}/{object_id}` | 详情 |
| `/api/img/{museum_id}/{object_id}` | 主图 |
| `/api/img/{museum_id}/{object_id}/{index}` | 多图 |

前端对接规则：**只用** API 返回的 `img_web`，不要用库里的 `image_path`。

本地 Demo 页：`gallery.html`、`web_demo.html`。

### 3.3 统一访问路径（执行全组第十二周决议）

| 消费方 | 怎么访问 |
|--------|----------|
| ② Web | 调本组 REST API |
| ③ 问答 | 调本组图谱检索 API，禁止直连 Neo4j |
| ④ App | 优先走 ② 后端，底层还是本组数据 |
| ⑤ 后台 | 读写 MySQL；改图库走本组同步脚本 |

标准链路已写入 README，② 万玉贤、③ 张芷淇需在 5.30 前完成图谱 API 冒烟。

### 3.4 第十三周服务器部署计划

全组决定下周把 MySQL、Neo4j、API、文物原图都迁到联调服务器 `47.96.152.190`，各组不再本地起库。

本组部署清单：

- MySQL 全量数据  
- Neo4j 全量图谱  
- FastAPI 进程（8000 端口）  
- 爬虫本地下载的原图，按馆别目录上传  

**图片托管**：②④ 反馈海外原站 `image_url` 加载太慢（常 5～10 秒），组会决议 API 优先返回服务器图片地址，原站链接仅作溯源。

目标：Web 列表首屏 ≤ 2 秒，App 详情 ≤ 1.5 秒。

### 3.5 图库建模（定稿）

节点：Artifact、Museum、Dynasty、Artist、Material、ArtifactType、Location、Culture 等  

关系 8 类：belongsToMuseum、belongsToDynasty、createdBy、usesMaterial、hasPrimaryMaterial、hasType、hasCulture、locatedIn  

详见 `BUCT-CS2303-SoftWareE-graph-db/docs/graph-database-design.md`。
