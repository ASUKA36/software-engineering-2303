## 三、本周会议决议

### 3.1 子系统职责确认

对照全组第八周决议，本组端到端负责：

- 三家博物馆文物数据采集（爬虫）  
- 数据清洗、去重、字段标准化  
- 三元组建模与 Neo4j 入库  
- MySQL 业务表构建与维护  
- 对外提供统一数据接口，供 Web、App、问答、后台消费  

**约束**：②③④ 不重复爬馆网；本组产出为全平台唯一文物主数据来源。

### 3.2 技术路线

| 模块 | 选型 | 备注 |
|------|------|------|
| 爬虫 | Python + requests | MFA 动态页后续考虑 Playwright |
| 关系库 | MySQL 8+ | 存文物明细及后续各组共用业务表 |
| 图库 | Neo4j | 存实体与关系，供问答和可视化 |
| 输出 | UTF-8 CSV | 对齐任务书附录字段要求 |
| 协作 | Git + Markdown 文档 | 接口变更须通知其他组 |

### 3.3 三馆调研结论（初稿）

| 博物馆 | 初步判断 | 主要难点 |
|--------|----------|----------|
| 史密森尼 | 有 Open Data / API，可走结构化采集 | 需申请 API Key；图片链接需单独处理 |
| 哈佛艺术博物馆 | 有 REST API，字段较规范 | IIIF 多图路径要单独解析 |
| 波士顿 MFA | 页面动态加载，反爬较重 | 可能需要浏览器自动化 |

### 3.4 工程目录规划

```
crawler/
├── museum_crawler/     # 核心包
├── museum_spider.py    # 统一入口
└── output/             # CSV、图片、KG 产出
```

知识图谱与API接口模块第十周后再建，本周先把爬虫骨架搭起来。
