## 三、本周会议决议

### 3.1 功能性需求

本组需求边界如下：

**数据采集**

- 至少覆盖史密森尼、哈佛、MFA 三家馆  
- 字段包括：名称、原图、年代、类型、材质、介绍、详情 URL 等，对齐任务书附录  
- 输出 UTF-8 CSV，附字段说明文档  

**数据清洗**

- 材质、朝代等字段做标准化  
- 按 `(museum_id, object_id)` 去重  
- 图片下载后做有效性校验  

**知识图谱**

- 实体：Artifact、Museum、Dynasty、Artist、Location 等  
- 关系：收藏于、创作于、属于朝代、材质为、类型为等  
- 建模思路参考 CIDOC-CRM，不追求完整复刻  

**存储**

- MySQL 存明细，Neo4j 存三元组  
- 本阶段先做全量导入，增量策略后补  

### 3.2 试爬结果

| 博物馆 | 试爬情况 | 结论 |
|--------|----------|------|
| 哈佛 | REST API 跑通，可稳定拉取 Chinese 相关藏品 | 作为主开发馆，优先完善 |
| 史密森尼 | S3 开放数据模式可用，API 需 Key | 正式爬取加 `--si-s3-only` |
| MFA | requests 基本抓不到有效链接 | 确认上 Playwright |

### 3.3 对外约束

- ②③④ 不得自行爬馆网，需要字段变更找本组改库或改 CSV 规范。  
- ③ 问答溯源用的 `detail_url`、`title` 等字段，本组 CSV 里必须保留且不为空（能填的尽量填）。

### 3.4 Neo4j 节点/关系清单（初稿）

**节点**：Artifact、Museum、Dynasty、Artist、Material、ArtifactType、Location  

**关系**（文件名暂用 camelCase）：

- belongsToMuseum、belongsToDynasty、createdBy  
- usesMaterial、hasPrimaryMaterial、hasType、locatedIn
