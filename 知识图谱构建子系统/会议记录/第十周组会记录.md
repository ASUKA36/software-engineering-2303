## 三、本周会议决议

### 3.1 概要设计（本组部分）

**数据层**

- MySQL：`overseas_chinese_artifacts.artifact` 表，34 标准字段，utf8mb4，主键 `(museum_id, object_id)`  
- Neo4j：节点维表 + 文物实体 + 8 类关系，导入脚本放 `BUCT-CS2303-SoftWareE-graph-db/scripts/`  

**服务层（规划，尚未实现）**

- 文物只读 REST API  
- 图谱关系查询 API（给 ③ 用，禁止外组直连 Neo4j）  
- 图库同步接口（给 ⑤ 修正数据后触发）  

**模块划分**

| 模块 | 主要文件 | 职责 |
|------|----------|------|
| 爬虫 | `smithsonian.py` / `harvard.py` / `mfa_boston.py` | 三馆采集 |
| 清洗 | `data_clean.py` / `material_normalize.py` | 标准化 |
| 入库 | `db.py` / `csv_db_sync.py` | MySQL UPSERT |
| 图谱 | `kg_export.py` / `neo4j_sync.py` | 三元组导出与同步 |
| 质检 | `quality.py` | 爬后检查 |

### 3.2 三馆爬虫实现进度

| 博物馆 | museum_id | 本周进展 |
|--------|-----------|----------|
| 史密森尼 | 1 | S3 主扫 + API 补漏，脚本可跑 |
| 哈佛 | 2 | REST + IIIF 多图解析完成 |
| MFA | 3 | Playwright 过 WAF，能出数据但速度慢 |

统一入口：`museum_spider.py`，支持 `--museums all --limit N`。

### 3.3 服务边界（同步全组第十周决议）

- 本组向 ②③④⑤ 提供文物查询和图谱查询能力。  
- ③ 不得直连 Neo4j，所有 Cypher 经本组 API 执行。  
- ⑤ 改 MySQL 业务数据后，图库同步走本组脚本，避免两边各写各的。

### 3.4 文档产出

- `graph-database-design.md`：图库节点、关系、URI 规则、导入顺序  
- MySQL 表结构草案：已发各组征求意见
